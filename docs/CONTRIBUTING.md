# Contributing to TI Mindmap HUB

Thank you for your interest in contributing to TI Mindmap HUB! This document provides guidelines for contributing to this research project.

## How You Can Contribute

### 1. Feedback and Bug Reports

The most valuable contribution is feedback on the platform's outputs.

**Report issues with:**
- Incorrect IOC extraction
- Wrong TTP mappings
- STIX bundle errors
- False positives/negatives
- UI/UX problems

**How to report:**
- Use the **Feedback** button in the platform
- Email [info@ti-mindmap-hub.com](mailto:info@ti-mindmap-hub.com)
- Open an issue in this repository (for documentation issues)

### 2. Documentation Improvements

Help improve this public repository:

- Fix typos or clarify explanations
- Add examples
- Improve methodology documentation
- Translate documentation

**Process:**
1. Fork this repository
2. Make your changes
3. Submit a pull request
4. Describe your changes clearly

### 3. STIX Examples

Contribute example STIX bundles:

- Real-world examples (sanitized)
- Edge case examples
- Integration examples for specific platforms

### 4. Academic Collaboration

We welcome academic contributions:

- Joint research papers
- Thesis supervision
- Evaluation studies
- Dataset contributions

Contact [info@ti-mindmap-hub.com](mailto:info@ti-mindmap-hub.com) to discuss.

### 5. Source Suggestions

Suggest new OSINT sources for monitoring:

- Security vendor blogs
- Government advisories
- Research publications
- Industry reports

Open an issue with the tag `source-suggestion`.

## Contribution Guidelines

### Code of Conduct

- Be respectful and constructive
- Focus on improving the project
- Assume good intentions
- Keep discussions professional

### Pull Request Process

1. **Fork** the repository
2. **Create a branch** with a descriptive name
   ```bash
   git checkout -b docs/improve-methodology
   git checkout -b fix/typo-in-readme
   ```
3. **Make your changes**
4. **Test** your changes (especially for documentation)
5. **Commit** with clear messages
   ```bash
   git commit -m "docs: clarify IOC extraction process"
   ```
6. **Push** to your fork
7. **Open a Pull Request** with a clear description

### Commit Message Format

Use conventional commit format:

```
type: description

[optional body]
```

Types:
- `docs`: Documentation changes
- `fix`: Bug fixes
- `feat`: New features
- `chore`: Maintenance tasks

### Documentation Standards

- Use Markdown formatting
- Include code examples where helpful
- Keep language clear and concise
- Update table of contents if adding sections
- Add "Last updated" dates to documents

## What We're NOT Looking For

To set clear expectations:

- ❌ Core application code (maintained privately)
- ❌ Feature requests requiring code changes
- ❌ Operational support requests
- ❌ Commercial partnership proposals (contact email instead)
